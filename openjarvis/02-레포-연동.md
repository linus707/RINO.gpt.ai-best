# 02. 이 레포(RINO.gpt.ai-best)와 연동하기

## 결론: 코드를 복사하지 않고 "옆에 두는" 방식
이 레포는 정적 웹사이트(HTML, 가격 JSON, 여행 지도 등)예요. OpenJarvis는 파이썬 + Rust + 프론트엔드가 섞인 149MB짜리 프로젝트라 합치면 레포가 무거워지고 업데이트도 어려워져요.
그래서 **원본은 별도 폴더에 clone하고, 이 레포에는 내 설정과 문서만 보관**해요.

```
~/projects/
├─ RINO.gpt.ai-best/     ← 내 사이트 레포 (설정·문서 보관)
└─ OpenJarvis/           ← 원본 (setup.sh가 자동 clone)
```

## 연동 지점

| 이 레포의 자산 | OpenJarvis에서의 활용 |
|---|---|
| `docs/content-plan-2026-11.md` (콘텐츠 플랜) | `jarvis memory index`로 색인하면 "이번 주 뭐 올리지?" 질문에 답변 |
| `docs/pos.md` 등 문서 | 같은 방식으로 색인해서 Q&A |
| `travel/`, `travel-map/` (여행 자료) | 블로그 글 초안 때 자료로 검색 |
| `prices.json`, `store-prices.json` | 가구 가격 문의 응답 초안에 참고 |
| `scripts/*.mjs` (알림 스크립트) | 예약 작업 결과를 알림과 연결할 때 참고 |

## 사용법

```bash
cd RINO.gpt.ai-best
bash openjarvis/scripts/setup.sh                 # 원본 clone + 의존성 + 설정 복사
jarvis memory index ./docs ./travel              # 내 자료 색인
jarvis ask "이번 주 가구 브랜드 콘텐츠 일정 알려줘"
```

## 설정 파일 고르기

| 파일 | 언제 |
|---|---|
| `configs/rino-chat.toml` | 처음 테스트할 때. 가장 가볍고 도구 없음 |
| `configs/rino-research.toml` | 블로그 자료조사. 웹검색과 내 문서 검색 사용 |
| `configs/rino-monitor.toml` | 매일 자동 실행. 트렌드·경쟁 채널 점검 |

적용은 `cp openjarvis/configs/rino-research.toml ~/.openjarvis/config.toml` 한 줄이에요. (기존 설정은 setup.sh가 백업해요.)

## 하지 않은 것 (의도적으로)
- 원본 소스 복사/서브모듈 추가: 레포 비대화 방지
- API 키·토큰 저장: 이 레포에 비밀값을 넣지 않아요. Gmail 등은 `jarvis connect`로 PC에서만 인증해요.
