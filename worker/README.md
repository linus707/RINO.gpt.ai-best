# 즉시 푸시 워커 (Cloudflare Workers)

메시지를 보내자마자 몇 초 안에 폰으로 알림을 보내는 작은 서버예요. 연결하지 않아도 GitHub Actions(`scripts/push-send.mjs`)가 5분 간격으로 같은 일을 하므로, 이 워커는 **선택**입니다. 둘이 함께 켜져 있어도 같은 메시지는 `push-state.json`의 `seen` 기록 덕에 한 번만 나가요.

## 동작
1. 앱이 메시지를 올리고 동기화가 끝나면 `POST /notify {"id": "<메시지 id>"}`만 보내요. (내용은 보내지 않아요)
2. 워커가 비공개 Gist에서 그 메시지와 기기 구독 목록을 읽어요. 아직 안 올라왔으면 최대 4번(1.5초 간격) 다시 읽어요.
3. 보낸 사람·멘션 없는 음소거 방·만료된 기기를 빼고 웹 푸시(RFC 8291 + VAPID)를 보내요.

가짜 요청으로는 알림 내용을 만들 수 없어요. 워커는 Gist에 실제로 있는 메시지에 대해서만 보내고, 허용된 Origin(`https://linuscompany.co.kr`)에서 온 요청만 받으며, IP당 분당 60회로 제한해요.

## 배포 (둘 중 하나)
**A. 대시보드(쉬움)** Cloudflare → Workers & Pages → Create Worker → 코드에 `worker.js` 전체를 붙여 넣고 Deploy.
**B. 명령줄** `cd worker && npx wrangler deploy`

## 비밀값 (Settings → Variables and Secrets, 유형 Secret)
| 이름 | 값 |
|---|---|
| `GIST_TOKEN` | 앱 동기화에 쓰는 GitHub 토큰 (Gist 권한) |
| `GIST_ID` | 동기화 Gist ID |
| `VAPID_PRIVATE_KEY` | 앱에서 푸시 키를 만들 때 한 번 보여 준 비공개 키 |

선택: `ALLOWED_ORIGIN`(쉼표로 여러 개), `VAPID_SUBJECT`(`mailto:…`). 토큰과 키는 채팅·문서·코드에 쓰지 말고 Secret에만 넣으세요.

## 연결
앱 설정 → 푸시 알림 서버 → **⚡ 즉시 푸시** 칸에 워커 주소(`https://….workers.dev`)를 넣고 저장 → **연결 확인**.
`GET /health` 가 `{"ok":true,"configured":true}` 이면 준비 완료예요.

## Notion 일정 연동 (선택)
앱 일정표와 Notion 데이터베이스(예: '스케쥴')를 서로 맞춰요. 같은 워커에 `/cal` 경로로 붙어 있어요.

### 동작
- 앱 ↔ Notion을 **양쪽으로** 맞춰요: 새 일정·수정은 양쪽에 반영돼요. 같은 일정을 양쪽에서 동시에 고치면 **앱 내용이 이겨요**.
- Notion에서는 **상태가 '일정 📅'인 항목**만 가져와요(할 일 항목은 가져오지 않아요). 앱에서 올린 일정은 같은 상태로 만들어져요.
- 앱에서 지운 일정은 Notion **휴지통**으로 가요(복구 가능). Notion에서 지운 일정은 앱에서 자동으로 지우지 않아요.
- 범위: 오늘 기준 30일 전 ~ 180일 후. 한 번에 앱→Notion 20건까지 올려요.
- Notion 키는 워커 Secret에만 있고, 앱에는 접속 키만 있어요. 접속 키가 없으면 누구도 일정을 읽거나 쓸 수 없어요.

### 준비 (한 번만)
1. **통합 만들기**: Notion → 설정 → 연결(또는 notion.so/profile/integrations) → 새 통합 → 유형 *내부* → 저장 → **내부 통합 시크릿** 복사. 필요한 권한은 콘텐츠 읽기·업데이트·삽입이에요.
2. **데이터베이스 연결**: 동기화할 데이터베이스 페이지 → 오른쪽 위 `···` → 연결 → 방금 만든 통합 추가.
3. **데이터베이스 ID**: 그 데이터베이스 주소(URL)에서 `?` 앞의 32자리 영문·숫자예요.
4. **워커 Secret 3개 추가** (Settings → Variables and Secrets, 유형 Secret):

| 이름 | 값 |
|---|---|
| `NOTION_TOKEN` | 1번의 내부 통합 시크릿 |
| `NOTION_DB_ID` | 3번의 데이터베이스 ID |
| `CAL_KEY` | 직접 만든 길고 무작위인 문자열(20자 이상). 앱에 넣을 접속 키와 같아야 해요 |

5. **워커 코드 갱신**: 대시보드에서 `worker.js` 전체를 다시 붙여 넣고 Deploy. `GET /health` 에 `"cal":true` 가 보이면 준비 완료예요.
6. **앱 설정**: 설정 → 연결·동기화 → *Notion 캘린더 연동* 에 워커 주소(비우면 푸시 워커 주소)와 접속 키를 저장 → **연결 확인** → **지금 동기화**.

토큰·키는 채팅·문서·코드에 쓰지 말고 Secret과 앱 설정 칸에만 넣으세요.

### Notion 데이터베이스가 갖춰야 할 것
제목 속성 1개, 날짜 속성 1개는 꼭 있어야 해요. 있으면 같이 맞추는 속성: 한줄메모(텍스트), 일정분류(선택), 상태('일정'이 들어간 옵션). 속성 이름은 자동으로 찾아요.
