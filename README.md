# Linus Company 워크스페이스

가구·침구 매장을 운영하는 **Linus Company**의 업무 앱이에요. 장부, 매장 POS, 가격표, 일정, 업무 대화를 한 곳에서 쓰고, 폰·태블릿·PC에서 앱처럼 설치해서 사용해요. (주소: https://linuscompany.co.kr)

서버를 따로 두지 않는 정적 사이트 구조예요. 데이터는 비공개 GitHub Gist로 동기화하고, 알림·로그인 같은 서버 일은 GitHub Actions와 Cloudflare Worker가 맡아요.

## 구성

| 파일·폴더 | 역할 |
|---|---|
| `index.html` | 메인 앱. 로그인, 홈, 장부, 일정(Celender), 업무 대화방, 컨텐츠·물품·재고, 설정 |
| `pos.html` | 매장 POS (제품 목록·장바구니·견적 비교·상담/판매 기록). `buy.html`은 여기로 넘어가요 |
| `price.html` + `prices.json`, `store-prices.json` | 제품 가격표(전체 정상가 / 매장 가격표). POS용 엑셀 양식은 `pos-price-*.xlsx` |
| `translate.html`, `ios/RinoTranslate/` | 키보드 번역 페이지와 아이폰 키보드 앱 |
| `japanese.html` | 일본어 회화 연습 앱 |
| `offline.html`, `sw.js`, `manifest.webmanifest`, `icon*` | 설치형 앱(PWA), 오프라인 안내, 웹 푸시 수신 |
| `scripts/` | 푸시 알림 발송, 배포 때 로그인 서버 주소 주입, 가격표 엑셀 생성 |
| `tests/` | 방화벽 보안 테스트 ([`tests/README.md`](tests/README.md)) |
| `worker/` | 즉시 푸시·로그인·Notion 일정 연동용 Cloudflare Worker (선택) |
| `extension/` | AMS 제품 표를 앱 단가표로 보내는 크롬 확장 프로그램 |
| `.github/workflows/` | `pages.yml`(배포), `push.yml`(5분마다 알림 발송), `security-tests.yml`(보안 테스트), `ios-build.yml`(아이폰 앱 빌드) |

## 주요 기능

- **장부**: 판매 기록(고객·연락처·주소, 제품 여러 개, 수량·할인율, 판매자, 배송 예정일), 결제(계약금·잔금·방식·취소), 미수금, 판매자·제품·월별 분석, CSV 내보내기(회계용 포함)
- **일정(Celender)**: 앱 일정표. 장부의 배송 예정일이 제품배송 일정으로 들어가고, Notion 데이터베이스와 양방향으로 맞출 수 있어요.
- **업무 대화방**: 공지사항·업무 대화·알림 방, 새 메시지 웹 푸시
- **계정·권한**: 이메일 회원가입 → 관리자 승인 → 역할(직원/관리자)별 메뉴. 컨텐츠·물품·재고는 관리자 전용이에요.
- **데이터 보호**: 자동 백업·복원, 휴지통, 백업 파일 받기·합치기, 설정 데이터 잠금
- **실시간 반영**: 앱이 열려 있는 동안 10초마다 다른 기기의 변경을 받아와요.
- **오프라인**: 업무 데이터는 기기에 캐시하지 않고, 오프라인 안내 페이지 하나만 캐시해요.

## 배포와 실행

- **배포**: `main` 브랜치에 푸시하면 `pages.yml`이 GitHub Pages로 올려요. 올라가는 파일은 워크플로의 `cp` 목록에 적힌 것(각 HTML 페이지, 가격표 JSON·엑셀, `sw.js`, 매니페스트, 아이콘, `CNAME`)뿐이에요. **새 페이지를 추가하면 이 목록에도 넣어야 해요.**
- **빌드 과정은 없어요.** `package.json`이 없고 `npm install`·`npm start`도 필요 없어요. HTML 파일을 그대로 올려요.
- **로컬 확인**: 저장소 폴더에서 간단한 정적 서버를 열어 `index.html`을 보면 돼요. 로그인·동기화·푸시는 Worker와 Gist 연결이 있어야 동작해요.

  ```bash
  python3 -m http.server 8000
  ```

- **푸시 스크립트 테스트**: `scripts/`의 파일은 Node.js 20과 `web-push` 패키지를 써요. 워크플로가 실행할 때 설치해요.

## 필요한 비밀값 (GitHub Secrets)

| 이름 | 용도 |
|---|---|
| `SYNC_GIST_TOKEN`, `SYNC_GIST_ID` | 동기화 Gist 읽기·쓰기 |
| `VAPID_PRIVATE_KEY` (`VAPID_SUBJECT`은 선택) | 웹 푸시 발송 |
| `SOLAMEN_READ_TOKEN` | AI 직원 진행 알림에서 지시함 저장소 읽기 전용 |

토큰과 키는 코드·문서·채팅에 적지 말고 Secrets에만 넣으세요.

## 알림 구조

`push.yml`이 5분마다 세 가지를 실행해요.

1. `push-send.mjs`: 새 업무 메시지를 웹 푸시로 발송
2. `staff-notify.mjs`: AI 직원이 지시를 '착수'·'보고'했을 때 대표 기기로 알림
3. `due-notify.mjs`: 미수금 알림 (아래 참고)

몇 초 안에 받고 싶으면 `worker/`의 즉시 푸시 워커를 연결하세요. 연결하지 않아도 위의 5분 간격 알림은 동작하고, 둘을 같이 켜도 같은 메시지는 한 번만 나가요. 설정 방법은 [`worker/README.md`](worker/README.md)에 있어요.

## 알아둘 점

서버 없는 구조라서, 로그인한 기기는 직원이든 관리자든 같은 동기화 키를 받아요. 메뉴 구분은 **화면 잠금 수준**이에요. 직원에게 숨기고 싶은 민감한 자료는 앱에 넣지 마세요.

## 미수금 푸시 알림
- `scripts/due-notify.mjs`가 `.github/workflows/push.yml`(5분마다)에서 함께 실행돼요. 동기화 Gist의 장부에서 잔금이 남은 주문 중 예정일이 지났거나 3일 이내인 건을 찾아, 정해 둔 시각(기본 한국 시간 9시) 뒤 첫 실행 때 하루 한 번 관리자 기기로 웹 푸시를 보내요.
- 기본 알림에는 건수와 잔금 합계만 담고, 고객 이름은 앱 설정(장부 > 결제·회계 > 미수금 푸시 알림)에서 켠 경우에만 넣어요. 필요한 비밀값은 기존 푸시와 같아요(`SYNC_GIST_TOKEN`, `SYNC_GIST_ID`, `VAPID_PRIVATE_KEY`).
- 알림을 누르면 `/?ledger=pay`로 열려 장부의 결제·회계 탭이 보여요.

## 키보드 번역
- `translate.html`: 한글은 고른 언어로, 외국어는 한국어로 바꿔 주는 번역 페이지예요(`/translate.html`). 번역할 글은 MyMemory 번역 서비스로 전송돼요.
- `ios/RinoTranslate/`: 같은 기능의 아이폰 키보드 앱(Swift) 프로젝트예요. 설치 방법은 그 폴더의 README를 보세요.

## 일본어 회화
- `japanese.html`: 리노 전용 일본어 회화 연습 앱이에요(`/japanese.html`). 홈·AI 회화·상황별 코스·발음 쉐도잉·단어장·마이페이지(학습 리포트) 6개 화면이고, 휴대폰 홈 화면에 추가하면 따로 앱처럼 열려요(`japanese.webmanifest`).
- 코스 6개(카페·편의점·길 묻기·호텔·친구 약속·비즈니스)의 대화와 쉐도잉 문장, 단어 20개는 파일 안 `COURSES`·`VOCAB`에 들어 있어요. 문장을 추가하려면 거기에 원문·가나 읽기·뜻을 넣으면 한글 발음은 자동으로 만들어져요.
- 듣기·말하기는 브라우저의 음성 합성·음성 인식을 써요. 발음 점수는 "인식된 문장이 목표 문장과 얼마나 같은지"로 계산해요.
- 'AI 자유 회화'만 Anthropic API 키가 필요해요(마이페이지 → 설정). 키와 학습 기록은 그 기기의 브라우저에만 저장돼요.

## 보안 방화벽
사이트는 두 겹으로 지켜요.
- **페이지 방화벽(콘텐츠 보안 정책)**: 모든 페이지(`index.html`·`pos.html`·`buy.html`·`price.html`·`translate.html`·`japanese.html`·`offline.html`) 맨 위 `Content-Security-Policy`에 적힌 주소로만 연결·불러오기가 돼요. 누군가 악성 코드를 끼워 넣어도 다른 서버에서 스크립트를 불러오거나 허용되지 않은 서버로 자료를 보내는 길이 막혀요. 다른 사이트가 우리 화면을 몰래 끼워 넣는 것(클릭재킹)도 막아요.
- **서버 방화벽(워커)**: 로그인·푸시·일정 서버로 오는 모든 요청을 먼저 걸러요. 자세한 규칙은 `worker/README.md`의 '방화벽'을 보세요.
- **새 외부 서비스를 붙일 때**: 그 페이지의 `connect-src`(연결), 글꼴·스타일이면 `font-src`·`style-src`에 주소를 추가해야 해요. 빠뜨리면 그 기능만 동작하지 않고, 메인 앱은 "보안 방화벽이 … 연결을 막았어요" 안내를 띄워요.
- 로그인 서버(워커)는 `*.workers.dev` 주소면 그대로 되고, 자체 도메인이면 배포할 때 `scripts/inject-auth.mjs`가 허용 목록에 자동으로 넣어요. Notion 연동 워커를 자체 도메인에 따로 둔다면 `index.html`의 `connect-src`에 직접 추가해 주세요.
- 한계: 앱이 한 파일 안의 인라인 스크립트로 되어 있어 `script-src`에 `'unsafe-inline'`이 들어가 있어요. 페이지 안에 직접 끼워진 스크립트의 실행 자체는 막지 못하므로, 화면에 넣는 값은 지금처럼 꼭 `esc()`를 거쳐야 해요.

## 매장 POS (`pos.html`)
- 2026-11-17에 예전 매장 POS를 새 화면으로 바꿨어요(흰 바탕·검정 알약 버튼·파란 선택 링 디자인). 홈페이지의 「매장 POS」 메뉴도 이 화면을 띄워요. 예전 주소 `buy.html`은 `pos.html`로 넘겨 줘요.
- **처음 화면 = 제품 목록**: 상단 메뉴를 누르면 그 메뉴의 모델이 카드(그림·모델명·코드·색상·규격 칩·가격)로 나열돼요. 시리즈 칩으로 거르고, 기본순·낮은 가격순·높은 가격순으로 정렬해요. 카드를 누르면 상세(왼쪽 갤러리 + 오른쪽 옵션)가 열리고, 브라우저 「뒤로」로 목록에 돌아와요.
- **메뉴 펼침**: 마우스를 쓰는 넓은 화면에서 상단 메뉴에 올리면 추천 상품 6개와 시리즈 목록(많은 순)이 펼쳐져요.
- **가격표**: 기본은 예전 POS에 들어 있던 **매장 가격표**(`store-prices.json`, 「매장POS_가격표_매장채움_2026-11-04.xlsx」 729줄)예요. 설정 › 가격표·검색에서 「전체 정상가 파일로」(`prices.json`, 약 2만 개)로 바꾸거나 엑셀을 불러올 수 있어요. 매장 가격표에는 사이드옵션이 없어서 기본 상태에서는 사이드옵션 메뉴가 비어 있어요.
- **예전 POS 데이터 옮기기**: 예전 POS를 쓰던 기기에서 처음 열면 예전 설정(할인율·페이백·별칭·매장 이름·수정 가격·사은품·숨긴 제품·매장이 만든 제품), 판매 기록, 상담 기록(진행 중 상담 포함), 불러온 엑셀, 사진을 한 번 옮겨 와요. 예전 데이터(`pos.`로 시작하는 저장값, `pos-photos`)는 지우지 않아요.
- **상담 단계 바**: 머리글 아래에 상담 번호와 ①상담 시작 → ②상품 담기 → ③견적 비교 → ④결제·기록, 「새 상담」이 보여요. 지금 할 단계에 파란 테두리, 끝낸 단계에 ✓가 붙고, 누르면 그 단계 창이 열려요. 제품 설정 › 메뉴 편집에서 끌 수 있어요.
- **견적서 인쇄**: 장바구니 위쪽 「견적서 인쇄」, 결제 확인 창의 「견적서 인쇄」, 기록 › 판매 기록의 「판매 내역 인쇄」로 A4 견적서(품목·할인율·할인 내역·결제 금액·할부·페이백·서명 칸)를 인쇄해요.
- **제품 설정 › 메뉴 편집**: 상단 메뉴 이름 바꾸기, ↑↓ 순서(맨 위 메뉴가 첫 화면), 숨기기, 새 메뉴 만들기·지우기, 기본 메뉴로 되돌리기.
- **제품 설정(전용 화면)**: 머리글 「제품 설정」(또는 설정 › 「제품 설정 열기」, 설정 비밀번호 필요)을 누르면 화면 전체가 제품 관리로 바뀌어요. 왼쪽은 제품 목록(검색, 메뉴별 칩, 「사진 없는·상세페이지 없는·가격 바꾼·숨긴·매장에서 만든 제품」 거르기, 제품마다 사진·상세·가격 표시), 오른쪽은 고른 제품의 편집 칸이에요. 탭은 **기본 정보**(이름·메뉴·설명·사은품 메뉴에 넣기·숨기기·삭제) / **가격·할인**(옵션별 판매가, % 조정, 이 모델 할인율) / **사진**(이 모델 전체 또는 고른 옵션만) / **상세페이지**(칸 편집 + 저장 전 미리보기). 「고객 화면에서 보기」로 바로 확인하고, 「새 제품·되살리기·백업」에서 새 제품 만들기·되살리기·사진 백업·테스트 모드를 써요. 「메뉴 편집」에서 위쪽 메뉴의 이름·순서·보이기, 새 메뉴 만들기·지우기, 기본 메뉴로 되돌리기, 상담 단계 바 보이기를 바꾸고(메뉴마다 「제품 n개 보기」로 왼쪽 목록 거르기, 주소 `?admin=1&menu=1`), 「가격표 엑셀 불러오기」에서 엑셀 가격표 불러오기·양식/매장 가격표 엑셀 내려받기·불러온 엑셀 지우기·전체 정상가 파일로 바꾸기를 해요(주소 `?admin=1&pl=1`). 주소는 `?admin=1&g=메뉴&m=모델`(새로 고치면 비밀번호를 다시 물어요). 설정창은 매장 전체 설정(할인·결제, 상품 관리, 검색 별칭)만 남았어요(「가격표·검색」 탭 맨 위에 가격표 엑셀 바로가기).
- **제품 설정 › 새 제품·되살리기·백업**: 새 제품 만들기(메뉴·모델명·규격·색상·정상가 — 같은 이름은 한 모델로 묶임), 매장에서 만든 제품 고치기·지우기, 이름·메뉴를 바꾼 제품 되돌리기, 삭제한 제품 되살리기, 사진 백업 내보내기·불러오기(예전 POS 백업 파일도 읽음), 테스트 모드.
- **제품 설정 › 기본 정보**: 가격표 제품의 이름 바꾸기, 다른 메뉴로 옮기기, 삭제(가격표 파일은 그대로, 되살리기 가능). 이 수정은 가격표를 다시 불러와도 남아요.
- **제품 설명**: 제품 설정 › 기본 정보 › 「설명」(200자까지)에 적으면 상세 화면의 제품 그림(사진) 안, 제품 아래에 3줄까지, 목록 카드에 2줄까지 보여요. 엑셀 가격표의 「설명」 칸으로도 넣을 수 있고, 설정에서 적은 설명이 먼저예요.
- **상세페이지(그림 아래)**: 상세 화면의 그림 아래에 「제품 상세」가 붙어요. 맨 위에 모델명과 설명, 그 아래에 매장이 만든 칸(사진·제목·내용)이 차례로, 맨 끝에 제품 정보(모델명·메뉴·규격·색상·가격 기준일)와 옵션별 상품코드·가격 표가 자동으로 나와요. 칸은 제품 설정 › 상세페이지에서 더하기·순서 바꾸기·지우기를 하고 「상세 설명 저장」을 눌러요. 칸 사진은 사진 백업 파일에 함께 들어가요. 휴대폰에서는 옵션 아래에 나와요.
- **테스트 모드**: 켜면 장바구니·견적·상담·판매 기록·가격 수정·사진을 실제와 따로(`buyt.`, `buy-photos-test`) 저장하고 위쪽에 노란 「테스트 모드」 표시가 떠요. 처음 켤 때 실제 설정·가격표를 복사해 가요. 비밀번호는 실제와 같아요.
- 상단 메뉴는 **매트리스 / 프레임 / 사이드옵션 / 슬립케어 / 사은품** 5개예요. 분류 묶음은 매장 POS 메뉴와 같고, 프레임에는 완성형 침대가 들어 있는 '침대세트(BS)'를 더했어요.
- 특정 상품은 주소로 바로 열 수 있어요: `/pos.html?g=frame&m=DADO-N(HT-R)` (`g`는 matt·frame·side·care·gift, 목록만 보려면 `?g=matt`, 시리즈는 `?g=matt&s=HT`).
- 전체 정상가 파일(`prices.json`)을 쓸 때는 이름 안의 규격(SS·DD·LQ…)과 그 뒤 색상으로 옵션을 묶어요. 가격표를 바꾸면 이 화면도 같이 바뀌어요.
- 이름에 「진열용」이 붙은 모델은 이 화면에 나오지 않아요(「진열장」 같은 상품 이름은 그대로 나와요).
- 사이드옵션은 모델 이름이 길고 많아서, 위 탭 줄에 고른 모델 이름 하나만 보여요. 다른 모델은 검색창으로 찾아요.
- 메뉴를 눌렀을 때 처음 보이는 모델은 파일 안 `GROUPS`의 `first`로 정해요(지금은 프레임만 `DADO-N(HT-R)`로 지정). 정하지 않으면 규격이 가장 많은 완성품이 나와요.
- **설정(오른쪽 위 ⚙)**: 지금 보고 있는 상품의 사진과 가격을 바꿔요.
  - 사진: 「이 모델 전체」(모든 규격·색상에 같은 사진) 또는 「고른 품목만」으로 넣고 뺄 수 있어요. 사진은 긴 쪽 1600px로 줄여 저장해요.
  - 가격: 옵션마다 금액을 직접 적거나, 「모든 옵션을 ○% 조정」으로 한 번에 바꿔요(천 원 단위 반올림). 「가격 저장」을 눌러야 적용돼요.
  - 비밀번호: 그 기기에서 처음 설정을 열 때 만들어요(4자 이상). 한 번 열면 10분 동안은 다시 묻지 않고, 새로 고침하거나 「지금 잠그기」를 누르면 다시 잠겨요. 5번 틀리면 30초 동안 막혀요. 비밀번호 자체는 저장하지 않고 암호화한 값만 저장해요. 잊었으면 「비밀번호를 잊었어요」로 지우고 새로 만들 수 있는데, 이때 그 기기의 사진·가격 수정도 함께 지워져요. 이 잠금은 그 기기의 설정창을 막는 용도이고 서버 보안은 아니에요.
  - 저장 위치: 이 기기의 브라우저(가격은 localStorage `buy.prices`, 사진은 IndexedDB `buy-photos`)예요. 다른 기기·손님 휴대폰에는 보이지 않고, 매장 POS의 사진·가격과도 따로예요.
- **장바구니(여러 제품 합산 할인)**: 상품마다 「장바구니 담기」로 여러 개를 담아요(오른쪽 위 장바구니 버튼). 계산은 매장 POS와 같아요.
  - 품목마다 제품 할인 → 지점 할인 → 매니저 할인을 **합산**(율을 더해 한 번에) 또는 **순차**(앞 할인 뒤 금액에 다음 할인)로 빼요. 방식은 설정 › 할인·결제에서 골라요.
  - 제품 할인율은 「품목 할인」(그 줄만) > 장바구니의 제품 칸(직접 바꾼 경우) > 모델별 할인율 > 메뉴별 할인율 > 기본 제품 할인율 순서로 정해져요.
  - 그다음 끝자리 절사(또는 직접 입력한 최종 금액) → 페이백(실부담금) → 할부(연 이자율이 있으면 원리금 균등) 순서예요.
  - 장바구니는 이 기기에 저장돼 새로 고침해도 남아요. 「견적 복사하기」로 전체 견적을 글로 복사해요.
- **사은품 메뉴**: 상단 5번째 메뉴예요. 가격표의 사은품 분류에 더해, 아무 상품이나 제품 설정 › 기본 정보 › 「사은품 메뉴에 넣기」를 켜면 여기에 모여요. 사은품 메뉴에서 담으면 **0원**으로 들어가고 할인 계산에서 빠져요(원래 메뉴에서 담으면 그대로 판매가예요).
- **견적 비교(A·B·C안)**: 장바구니 위쪽 「＋ 견적 저장」으로 지금 구성을 A안으로 저장하고, 「＋ 안 추가」로 복사본(B·C안)을 만들어 상품·할인·할부를 바꿔 봐요. 보고 있는 안은 장바구니를 바꿀 때 같이 저장돼요. 「비교」를 누르면 정상가·할인·결제 금액·할부·페이백·실부담금을 나란히 보여 주고, 가장 낮은 안에 표시가 붙어요. 「비교 견적 복사」로 글로 복사할 수 있어요.
- **손님 화면**: 장바구니의 「손님 화면」(또는 견적 비교의 「손님 화면으로」)을 누르면 태블릿을 손님 쪽으로 돌려 보여 줄 화면이 떠요. 견적 안이 있으면 안마다 카드로, 없으면 지금 장바구니 한 장으로 보여 줘요. 지점·매니저 할인 구성은 숨기고 「할인 합계」 한 줄만 보여 주고, 실부담금이 가장 낮은 안에 「가장 부담이 적어요」가 붙어요. 「인쇄」로 이 화면만 인쇄할 수 있고, 「직원 화면으로」(또는 Esc)로 돌아가요.
- **상담 기록**: 장바구니 맨 위 「상담 C1117-01」 줄을 눌러 방문 목적·유입 경로·메모를 넣어요(손님 이름·연락처·주소는 받지 않아요). 「상담 끝내기」로 보류(이유·재방문 예정일)·이탈을 남기면 장바구니·견적 안을 비우고 새 상담이 시작돼요.
- **결제 기록**: 장바구니의 「결제·판매 기록」에서 결제 금액을 확인하고 결제 수단(기록용)을 고른 뒤 「판매 기록 저장」을 누르면 판매 기록이 남고, 그 상담은 자동으로 「계약」이 돼요. 실제 결제는 매장 단말기에서 해요.
- **기록 보기**: 오른쪽 위 「기록」(설정 비밀번호 필요) → 상담 기록(이번 달 상담·계약·계약률·재방문 예정, 유입 경로별 계약률, 보류·이탈 이유, 전체 목록) / 결제 기록(건수·합계, 목록). 항목을 누르면 자세히 보이고, 보류 상담은 「이 견적으로 다시 상담(재방문)」, 판매 기록은 「장바구니로 불러오기」가 돼요(오늘 가격·설정으로 다시 계산). CSV로 내려받을 수 있어요(`consult-records_날짜.csv`, `sales-records_날짜.csv`).
- 기록은 이 기기에만 저장돼요(각 최근 500건). 매장 POS의 상담·주문 기록과 이어지지는 않아요.
- **엑셀 가격표**: 제품 설정 › 「가격표 엑셀 불러오기」 › 「엑셀 가격표 불러오기」로 .xlsx(「가격표」 시트, 없으면 첫 시트) 또는 .csv를 불러와요. 1행 제목에 **메뉴·모델명·정상가(원)**은 꼭, **순서·규격·색상·할인율(%)·검색어·상품코드·설명**은 있으면 써요. 「엑셀 양식 내려받기」는 예시 5줄이 든 서식(`pos-price-template.xlsx`), 「매장 가격표 엑셀로 받기」는 지금 매장 가격표 729줄을 같은 서식으로 옮긴 파일(`pos-price-store.xlsx`)이에요. 두 파일은 `python3 scripts/make-price-xlsx.py . .`로 다시 만들어요(store-prices.json을 바꿨을 때). 확인 창에서 메뉴별 줄 수와 오류 줄을 보여 주고, 적용하면 이 기기에서는 그 가격표만 써요(엑셀의 할인율 칸은 모델별 할인율 다음 순서로 적용). 「기본 가격표로 되돌리기」로 prices.json으로 돌아가요.
- **검색**: 영문 모델명·상품코드·규격과 한글 별칭(라노떼→LANOTTE, 로얄에이스→RA, 라지퀸→LQ 등 기본 75개 + 매장이 더한 별칭)으로 찾고, 영문은 1~2자 오타도 찾아요. 결과가 여러 개면 목록에서 고르고, 「라노 라지퀸」처럼 규격을 같이 쓰면 그 규격으로 열려요. 별칭은 설정 › 가격표·검색에서 더하고 빼요.
- **화면 정리(디자인)**: 상품 화면에서는 규격·색상·수량만 고르고, 할부·페이백은 장바구니에서 계산해요. 위 띠에는 할인이 있으면 「판매가(줄 긋기) → 할인 적용가」, 없으면 「합계」가 보여요. 휴대폰에서는 검색창이 한 줄 전체를 써요.
- **설정 › 할인·결제**: 구역(적용 방식·제품 할인율·지점·매니저·결제·페이백)을 눌러 펼치고 접어요. 접혀 있어도 오른쪽에 지금 값(예: 「기본 10% · 프레임 12%」)이 보이고, 「모두 펼치기」로 한 번에 열 수 있어요.
- **장바구니 아래쪽**: 「비우기」는 위쪽 제목 옆에 있고, 버튼은 손님 화면 · 견적 복사 · 결제·판매 기록 한 줄이에요. 휴대폰에서는 할인 내역을 접어 결제 금액·실부담금만 보여 주고, 위 요약 줄(정상가 · 할인 · 페이백)을 누르면 펼쳐져요.
- **설정 탭**: 「할인·결제」(적용 방식·기본·메뉴별 할인율·지점·매니저 기본값·할부 이자·끝자리·페이백) / 「상품 관리」(매장 이름·숨긴 상품·사은품 목록·모델별 할인율 목록·초기화) / 「가격표·검색」(엑셀 가격표·검색 별칭). 매장 POS의 같은 이름 설정과 값이 이어지지는 않아요(각자 따로 저장).
- 결제는 받지 않아요. 상품 화면의 「이 상품만 견적 복사」는 할인 전 금액, 장바구니의 「견적 복사하기」는 할인·할부·페이백까지 넣은 금액이에요. 배송비는 넣지 않았어요.
- 제품 그림은 메뉴마다 예시 그림 한 장이에요(규격이 커지면 폭만 넓어져요). 실제 제품 사진은 아직 없어요.
